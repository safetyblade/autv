# Cast media loading and local recovery

The session/discovery and receiver application ID are unchanged. `CastSender.load` now prepares only public FAST media, identifies HLS/DASH/progressive MIME from a bounded HTTP response/manifest and passes the corresponding live/buffered type into the existing Google Cast SDK. Observed HLS EXT-X-MAP data supplies fMP4 segment hints. A fresh bounded redirect walk occurs for every attempt; the receiver gets the supplied terminal URL without re-encoding or dropping its parameters. Signed targets are ephemeral, never copied into the guide, Favourites or logs. Resolver cancellation closes the active HTTP call. Dedicated HTTP has no account headers or shared cookies; user-info URLs and unsafe redirects fail locally. Valid encoded macro fields are probed unchanged: accepted public streams are not rejected merely because a placeholder is present. Malformed URLs requiring sender expansion fail explicitly; no identity/IP values are fabricated.

A successful LOAD response is not playback. Matching PLAYING confirms ownership. Paused-only initial state, buffering and missing status retain local playback and have a 30-second watchdog. Status polling covers missing callbacks. Echoed load-generation tags correlate normal results; when customData is omitted, a ticketed LOAD acknowledgement, matching media and fresh SDK media session are required. The SDK exposes that session number via public MediaStatus.toJson; the status body is not exported. Superseded tickets cannot stop or take ownership of a newer tune. A previously matching PLAYING receiver session can be adopted explicitly.

Receiver rejection, sender HTTP access failure, unsupported format, required sender parameters, timeout and remote stop are separate safe categories. Only numeric SDK/HTTP detail and allowlisted reason labels reach UI/logs, never arbitrary receiver status messages, signed URLs, cookies or tokens. Buffering/unknown state after successful playback is also watched; disconnect restores local playback. Failed initial transfer reuses still-running local media rather than restarting it; a failed guide-preview transfer preserves the existing guide recovery choice. Account-bound native media is guarded both at sender load and MediaInfo creation, and connecting Cast does not interrupt a native channel already playing locally.

Validation uses focused JVM tests, local HTTP redirect/MIME fixtures, the actual Cast SDK MediaInfo envelope, and the real Android PlaybackModel/Media3 player with an explicitly fake receiver transport. CI runs CastPlaybackTest and ProviderPlaybackTest only for focused handoff regressions; it does not rerun public Media Lab samples. These tests do not prove physical Chromecast video/audio, CORS or codec compatibility. This execution did not use a physical receiver. Owner-device acceptance remains: select an ordinary public FAST HLS channel, connect the already-discoverable receiver, verify remote video/audio, then interrupt/reject receiver loading and check automatic local recovery. Some sources require credentials/headers or sender macro expansion that the generic receiver cannot obtain; those remain local with an explicit reason.
