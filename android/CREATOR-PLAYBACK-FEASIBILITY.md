# Creator playback feasibility — 15 October 2026

Recommendation: **revise and continue the isolated prototype; do not ship unified embedded TV playback yet.** Official-app handoff is the smallest supported first integration. YouTube has a documented Android WebView path worth testing. Twitch embedding requires genuine HTTPS hosting and has no demonstrated TV remote solution here. Neither belongs in the public M3U or Media3's HLS path.

## Established options

| Option | Compatibility, operation and maintenance assessment |
| --- | --- |
| YouTube IFrame API | Official Android WebView path; phone/tablet credible, TV player focus/consent/remote support unverified. Keep official controls/branding/advertising visible; use user initiation. Embed needs no Data API key; discovery does. Documented local-HTML/app-ID Referer needs no hosted page. Back must exit player to AUTV. Region, age/account restrictions, cookies, WebView/Play-services integrity and API errors remain platform-controlled. No transfer through AUTV's HLS Cast receiver. |
| Twitch web embed | Requires real HTTPS page and matching parent; minimum 400×300. Local files or fabricated parents are not a supported substitute. Static hosting can carry official player/events; no database needed. Mobile needs interaction. Preserve player/advertising unobscured. TV focus/Back/WebView compatibility remains unverified. Domain, consent/login and evolving player add maintenance. No direct native Media3/default-receiver Cast path established. |
| Official app intents | Twitch documents `twitch://stream/<login>`; YouTube watch/channel HTTPS ACTION_VIEW targets official packages, then HTTPS handler. Catch missing handlers. No key/quota/backend required. Apps own ads, restrictions, login and any Cast support they offer. Phone/tablet straightforward; TV depends on installed official handlers and their link support. Back/task behaviour needs device tests; this is a handoff, not an in-AUTV player. |
| Twitch Helix Get Streams | Metadata only. Needs matching Client-Id and app or user token; supports up to 100 logins/IDs. Successful empty filtered data means offline; auth/network/rate-limit failure means unknown. Local viewer OAuth is possible without client secret. Anonymous app-token service requires secure server credentials. Batch/cache on demand, never per-row polling. Tokens grant no playback/Cast rights. |
| YouTube Data API | Search with channelId/type=video/eventType=live, then videos.list validates owner, live state and embeddability. Public reads use API key without viewer OAuth. No result means no public live broadcast, not proof no restricted broadcast exists. Cache discovered IDs; revalidate cheaply. Current official quota page specifies a separate default 100 search calls/day at 1 per call, plus 10,000 units/day for other endpoints; inspect project quota before release. APK keys are extractable and local caching cannot cap aggregate usage. |
| Android libraries | Maintained `PierfrancescoSoffritti/android-youtube-player` latest listed release 13.0.0 wraps IFrame, supports app-package origin and missing-Referer errors; its baseline fits AUTV minSdk 24. It is third party, not TV certification or policy exemption. Its Cast module is separate, not evidence AUTV's receiver supports YouTube. No maintained official native Twitch playback SDK was established by the reviewed docs. Direct iframe keeps this experiment dependency-free. |

## Minimal prototype

`app/src/debug/java/dev/prestwich/autv/creator/` contains CreatorChannel, CreatorAvailability and CreatorPlaybackActivity. Debug manifest has one explicit activity declaration; release has no creator code. No new dependency, hosting, database or production guide entry.

Catalogue: Games Done Quick (`gamesdonequick`) and official WWE YouTube channel (`UCJ5v_MCY6GNUBTO8-D3XoAg`). [GDQ](https://gamesdonequick.com/) is official gaming content; [WWE viewing guidance](https://www.wwe.com/article/how-to-watch) confirms official YouTube wrestling events. WWE live events are intermittent; no currently live video ID is claimed. Runtime discovery selects an actual current broadcast or reports no public live broadcast. The debug shared source model distinguishes HLS/Twitch/YouTube; existing FAST Channel is deliberately not migrated.

Build/install debug, choose a FAST channel in normal AUTV, then:

```sh
adb shell am start -n dev.prestwich.autv/.creator.CreatorPlaybackActivity
```

The lab has no launcher/production-guide entry. Its temporary credential dialog accepts your YouTube Data API key and/or Twitch Client ID/user OAuth token. Credentials are memory-only, not logged or passed in intents; no OAuth onboarding/token minting is included. Check live is explicit, without polling. API/network/quota/parse failure remains Unknown; empty successful results give Offline; embedding restriction gives Unavailable; validated current result gives Live.

On phone/tablet a current embeddable WWE video enables Play here: official IFrame API, installed app ID HTTPS baseURL/Referer, native player controls, no autoplay or native JavaScript interface. End/error events change status. Back destroys embed; next Back leaves lab. Background destroys WebView. Official app remains available for unknown/offline/restricted cases; no handler shows a message. Twitch uses official-app fallback because no genuine hosted parent exists. TV uses fallback pending embed validation. No current livestream is manufactured to demonstrate success.

## Smallest integration design

1. Curated native catalogue with stable `twitch:<login>` / `youtube:<channelId>` identities. Start with a separate Creators guide action; do not add fake numbered HLS rows or change public outputs.
2. Dedicated creator controller/activity retains previous FAST selection/player in PlaybackModel; pause local HLS before platform playback, resume same channel on return. For active FAST Cast, explicitly tell users it remains playing or require disconnect. Never send platform IDs to HLS receiver. Production task/PiP/dual-audio behaviour needs verification.
3. Reuse rememberRemoteOk unchanged: short release opens, long toggles namespaced membership. Extend Favourites at typed identity boundary while preserving existing stored keys. Do not invent stream URLs to satisfy ChannelTuning/FavouriteIdentity.
4. Preserve Full EPG current/non-current selection semantics. Creators without schedules display status, not invented programmes. Return focus to originating creator row; retain FAST selection separately.
5. Query on selection/explicit refresh; coalesce duplicate requests, cache briefly (e.g. 2–5 minutes), revalidate known YouTube IDs before spending search quota, invalidate on ended/deleted/error with discovery cooldown. No offscreen polling. Lab intentionally has no polling/cache engine.

Backend decision: no backend for official-app handoff or known-video YouTube embed. Local on-demand discovery suffices for a small developer trial with supplied credentials, but cannot guarantee shared production quota. Demonstrate usage before adding a tiny cached metadata endpoint or curated current IDs. Anonymous Twitch Helix status needs server-held app credentials unless viewer OAuth is implemented. Twitch embed needs static HTTPS hosting, not database infrastructure. No general resolver/scraping/token extraction is warranted.

Required before production: authenticated discovery of a genuine current official broadcast; phone/tablet video/ad/consent/account/failure flows; real TV focus, Back and short/long OK; exact FAST return without unwanted PiP or dual audio; Cast coexistence/disconnect/failure; offline/end transitions and quota exhaustion. Compilation and fixtures do not establish these.

FAST can remain isolated because release code, ownership and catalogue are unchanged. Seamless embedded Twitch+YouTube TV playback is **not established**. Build an official-app-first curated entry point after device validation, continue YouTube embed experimentation, and defer Twitch embed until hosting and TV usability justify it.
